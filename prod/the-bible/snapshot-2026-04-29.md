```text
boundary = hidden[0, -1, :] -> [H], CPU float32
```

For Gemma-4, `self._crystal_layer == 13`. It writes:

```text
boundaries/window_NNN.npy        [H],    float32
residual_streams/window_NNN.npy  [S,H],  float32
activation_routes/window_NNN.npy [H],    float16
activation_routes.npy            [N,H],  float16
```

Route construction uses [mean_pool_hidden](/mnt/c/Users/jehma/Desktop/lazarus/chuk-lazurus/src/chuk_lazarus/inference/context/knowledge/activation_routes.py:19):

```text
pooled = sum(hidden * mask) / clamp(sum(mask), min=1)
pooled = L2-normalize(pooled, eps=1e-12)
```

Live route output is `mean_pool_hidden(stream, ones_mask, normalize=True, out_dtype=torch.float16)`, squeezed from `[1,H]` to `[H]`: [live_indexer.py](/mnt/c/Users/jehma/Desktop/lazarus/chuk-lazurus/src/chuk_lazarus/session_store/live_indexer.py:691).

**3. Retrieval And Routing**

Query vector construction: [interactive_memory_chat.py](/mnt/c/Users/jehma/Desktop/lazarus/chuk-lazurus/scripts/interactive_memory_chat.py:340)

The user prompt is tokenized without special tokens, passed through:

```python
capture_post_crystal_boundary(model, query_ids, crystal_layer=13, return_stream=True)
```

Then pooled with an all-ones attention mask:

```python
mean_pool_hidden(stream, mask, normalize=True, out_dtype=torch.float32)
```

Result:

```text
activation_query_vector = [1,H], float32, L2-normalized
```

Activation routing uses [activation_topk](/mnt/c/Users/jehma/Desktop/lazarus/chuk-lazurus/src/chuk_lazarus/inference/context/knowledge/activation_routes.py:68):

```text
query:  [1,H] or [H] -> [H]
matrix: [N,H]
query_f  = normalize(query.float32)
matrix_f = normalize(matrix.float32)
scores   = matrix_f @ query_f -> [N]
topk(scores)
```

`asi_route_candidates()` partitions stores: activation-backed stores use `_score_activation_windows()` and do not instantiate `TFIDFRouter`; legacy stores still use TF-IDF: [asi_router.py](/mnt/c/Users/jehma/Desktop/lazarus/chuk-lazurus/src/chuk_lazarus/session_retrieval/asi_router.py:1031).

For activation candidates:

```text
raw_score = activation cosine
raw_tfidf_score_pre_normalization = 0.0
activation_score = cosine
telemetry.route_source = "activation"
```

The Lexical Gate is in [interactive_memory_chat.py](/mnt/c/Users/jehma/Desktop/lazarus/chuk-lazurus/scripts/interactive_memory_chat.py:311):

```python
if top_tfidf_score > 0.0:
    allow
else:
    allow if top_activation_score >= 0.45
```

So a strong activation cosine bypasses a TF-IDF score of `0.0`. The current default activation threshold is `0.45`: [interactive_memory_chat.py](/mnt/c/Users/jehma/Desktop/lazarus/chuk-lazurus/scripts/interactive_memory_chat.py:223).

Ranking also preserves activation strength: `raw_score` enters `boosted_norm`, weighted at `0.35`, while lexical TF-IDF contributes only `0.05`: [asi_router.py](/mnt/c/Users/jehma/Desktop/lazarus/chuk-lazurus/src/chuk_lazarus/session_retrieval/asi_router.py:1101).

**4. Injection And Readout Physics**

KV_DIRECT materialization source is the store `injection_layer`. For Gemma-4 that is Layer 13. Runtime target is `source_layer + 1`, therefore Layer 14.

`gather_selected_residuals()` enforces `source_layer == store.config.injection_layer`: [torch_residual_bounded.py](/mnt/c/Users/jehma/Desktop/lazarus/chuk-lazurus/src/chuk_lazarus/inference/backends/_torch_residual_bounded.py:501). In stream mode it loads `[S,H]` residual streams, not only final boundaries.

`materialize_kv_direct()` projects archived residuals through the target attention K/V projections for `target_idx = source_layer + 1`: [torch_residual_bounded.py](/mnt/c/Users/jehma/Desktop/lazarus/chuk-lazurus/src/chuk_lazarus/inference/backends/_torch_residual_bounded.py:798). The produced tensors have:

```text
K,V = [1, n_kv_heads, archived_slots + 1_sink, head_dim]
```

The zero sink occupies prefix slot `0`; memory window ranges are offset by `+1`.

Runtime patches attention forward in `generate_with_kv_direct_materialization()`. Archived K/V are concatenated before fresh K/V at the patched layer, attention scores are computed against the enlarged key axis, and tier masks/hot bonuses are applied to the prefix slice: [torch_runtime.py](/mnt/c/Users/jehma/Desktop/lazarus/chuk-lazurus/src/chuk_lazarus/inference/backends/torch_runtime.py:2334).

For Gemma-4, the intended attention steering surface is Layer 14. Comments in the live chat path identify downstream full-attention followers as `19, 24, 29, 34`, inheriting from Layer 14 shared K/V semantics: [interactive_memory_chat.py](/mnt/c/Users/jehma/Desktop/lazarus/chuk-lazurus/scripts/interactive_memory_chat.py:991).

The “hexagon gullies” readout test currently uses two interventions: [test_e2e_ghost_recall.py](/mnt/c/Users/jehma/Desktop/lazarus/chuk-lazurus/tests/inference/backends/test_e2e_ghost_recall.py:168)

```text
attention steering:
  apply_ghost_activation(..., layer_idx=14, surface="self_attn_pre")

late readout:
  apply_ghost_activation(..., layer_idx=None, surface="final_norm_output")
```

So the late factual extraction path is currently Final LayerNorm output, not Layer 29 `o_proj`. The hook modifies only the final token vector before LM head readout: [retriever.py](/mnt/c/Users/jehma/Desktop/lazarus/chuk-lazurus/src/chuk_lazarus/session_retrieval/retriever.py:192).

I did observe one initial flaky failure in `test_enqueue_starts_worker_and_processes_window`: the test saw the boundary file before the keyword shard was present. The isolated rerun passed, and the full rerun passed.

Sparse live stores are numerically safe but semantically loose. `_compact_activation_routes()` creates a zero-filled `[rows,H]` float16 matrix and fills only present window rows: [live_indexer.py](/mnt/c/Users/jehma/Desktop/lazarus/chuk-lazurus/src/chuk_lazarus/session_store/live_indexer.py:1004). `activation_topk()` normalizes with `eps=1e-12`, so zero rows remain zero and produce cosine `0.0`, not NaN. It does not explicitly mask zero rows. `_score_activation_windows()` skips out-of-range IDs and skips IDs absent from `window_tokens`, and the interactive gate rejects all-zero activation unless a real candidate reaches `>=0.45`.

Remaining operational bottlenecks are local-model and runtime related: live activation query routing requires a model forward per user query; archival capture requires Torch/Gemma access; KV_DIRECT materialization and the end-to-end ghost recall path are CUDA-oriented; the workflow tools `bd` and `tinydex` function through WSL in this repo. No external embedding service is required for the activation-route path.
